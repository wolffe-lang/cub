cb12 prediction, before implementation

FALLEN will start at death age 30, after the unchanged 30-tick fade. An original seven-row, six-letter block word will be red on black, rich blocks and plain #, with no title/menu changes. It will hold for 20 ticks before a key can skip. The existing opening_aperture schedule will run backwards over the word, ending closed before the ordinary den respawn. Death mark and archive writes will remain at the original death tick; only respawn is delayed. Existing death replays and downstream frames may change and will be named, never silently regenerated.

The scent counter will be transient presentation state, not a saved currency. A deterministic integer batch will cover every intermediate value over min(distance,20) simulation ticks, including spending, with a retarget starting from the last rendered value. The simulation, save, score and replay values remain immediate. Live batches will render every integer without extra simulation/audio/save/replay ticks; headless batches will enumerate the same values as golden frames. Gains 1,8,30,300,1000 should take 1,8,20,20,20 ticks and render exactly that many integer values. 1000 needs 50 presentation frames per tick: terminal throughput may exceed the tick budget; measure and report without delaying simulation intentionally.

Expected additions: one counter module, local sim/art/cub seams, schedule/death tests, two-tier death/HUD golden sequences and a replay determinism witness.
